I don't use LLMs.
I conduct them.

You're not reading a claim — you're reading my actual telemetry. Every number below was extracted by an LLM agent that parsed — of my own Claude Code session transcripts. It read only metadata: token counts, tool calls, timestamps. No prompts, no content, nothing identifying. The dashboard about how I use LLMs was built by one.

01 — scale

Tokens are the new unit of work

Output is what the models actually produce; cache reads are the fingerprint of long-running agentic sessions that re-read huge context instead of one-shot prompting. Daily output tokens — every bar is a day of directed work.

02 — orchestration

A fleet, not a chatbot

The interesting verbs aren't "ask" and "reply." They're spawn, search, edit, verify. This is the tool-call distribution across every session — the shape of an operator wiring models into systems.

Four models, chosen by job and economics — Opus tiers for hard reasoning, Haiku for cheap high-volume passes. Model selection is a habit, not a setting.

03 — breadth

Across everything I build

The same operating model spans CAD generation, financial knowledge graphs, robotics perception, research systems. Project names anonymized; the work is real. Sized by output tokens.

04 — rhythm

When the fleet runs

Activity by hour of day — including the autonomous agents that keep working while I don't.

05 — the meta

How this page came to exist

🜂 Self-referential by design

I asked an LLM agent to answer "how do you use LLMs?" — and instead of writing prose, it wrote build_data.py, streamed — JSONL transcripts of my own work, aggregated — tokens of activity, anonymized every project, and rendered what you're looking at. The medium is the message.

Privacy: the extractor touches only counts and tool names — never the text of a prompt, file, or response. Everything shipped here is an aggregate. The source is open so you can check.
